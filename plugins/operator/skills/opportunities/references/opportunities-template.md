# Opportunities backlog template

Default path `docs/OPPORTUNITIES.md` (or your CONFIG-named backlog).

```markdown
# Opportunities — <YYYY-MM-DD>
*Operator-generated candidate backlog. **Ranked against the objective: <objective>.** Proposed only — dispatch is human-gated. Every item cites live evidence; mark unverified ones "lens-reported — verify before dispatch."*

> **Biggest lever may be off-data:** <if the fastest move toward the objective is outreach / a pilot / narrative, name it here>

## Ranked (advances the objective)
### 1. <title>
- **Problem / opening:** <what's leaking or missing>
- **Evidence:** <the number> (<source>, <date>)
- **Proposed action:** <the concrete move>
- **Target repo:** <one of your downstream repos> — or **a new project** if the work is a distinct product surface that fits none (standing up a new repo is a human decision)
- **Impact / effort:** <H/M/L> / <H/M/L>
- **Strategy fit:** <how it serves the current objective>
- **Status:** proposed

### 2. ...

## Parked (off-objective — revisit if the objective changes)
*Real finds that don't advance the current objective — kept so they're not lost, not pretended to be priorities.*
- <item> — <one line + why parked>

*Last updated: <YYYY-MM-DD>.*
```

Notes:
- **Deepen the top 1–3 before surfacing** — run the next layer of digging yourself (the precise number, the concrete action) so each is actionable, not a lead that bounces questions back.
- If a sweep surfaces nothing new, say so — a short honest backlog beats a padded one.
